## Clocks, admission and accounting

One append-only, SHA-linked ledger covers both stages. A single supervisor owns writes; same-directory hard-link publication of fully serialized, closed, fsynced temporary bytes prevents a duplicate event from overwriting evidence. The P02D-only helper uses os.link with no overwrite fallback. Pending files end in .pending and never match committed ledger JSON names; readers only consume final names. Historical writers and evidence are unchanged. A durable dispatch consumes its slot before child startup for the first slot, and before any subsequent feature command. Durable admission precedes the command permitting computation. Unknown dispatch/admission consumes the slot. Feature input-position and answer output-cap reservations are cumulative and never returned for failures.

Residency is conservative **worker lifetime**, from just before process creation through final wait; it includes cached-file verification, load, idle handshake, warm-ups, CPU work, serialization, synchronization, cancellation and cleanup. Session-end elapsed seconds are charged once. Nested load/forward/generation timings are descriptive components, never added again to that charge. Warm-ups are explicitly charged passes. GPU memory values will be descriptive worker measurements, not a scalar tariff.

Execution wall time is `perf_counter` from the one authorized supervisor invocation through end reporting; it includes between-worker validation. Offline code preparation/initial plan validation is separate. No automatic restart is supported. An unfinished session reports its last durable heartbeat as a measured lower bound, with the remainder unknown. An interrupted or corrupt ledger, unresolved slot, prior incident, or unsafe cleanup rejects more dispatch. Re-reading completed events never recharges them. Any later recovery decision needs review; it cannot reopen consumed slots.

Before an answer, reserve 300 seconds (150 load/startup, 120 generation, 30 cleanup), 2,048 output tokens, and evidence headroom. Before feature-worker startup reserve 300 seconds; before every later forward reserve 150 seconds (120 forward + 30 cleanup) within the feature sublimits and combined budget. Actual feature-worker elapsed time is included when reserving its next forward. This is an admission policy, not a mathematical hard service-time support bound.

Loader/readiness deadline is 150 seconds. Answer timeout is 120 seconds, with up to ten additional seconds to observe cooperative return, then kill/wait; finite cleanup waits are 30 seconds. Thus cancellation overhead may exceed the initial 300-second reservation: it is measured, never clipped, and future admission uses actual elapsed costs. A known answer timeout may retain a valid parsed result; known forced generation termination is an explicit retained zero with unknown output-token count, never fabricated raw output. A loader failure, callback error, unexpected child exit, corrupt result or evidence/monitor error is unscored and stops. A feature timeout, partial stage or invalid vector stops before all answers. Watchdogs reserve cleanup headroom against the combined/feature ceilings and persist overshoot. Failed kill/wait leaves unsafe/unknown residency and blocks continuation.

The supervisor's `finally` attempts child stop/wait even after monitoring/evidence errors and independently writes a session resource record before extending the main ledger. If storage is itself unwritable, ordinary persistence cannot be guaranteed: existing ledger and worker stderr remain evidence, the invocation fails, and dispatch closes; absence is an integrity incident. No implementation can turn a total storage failure into a valid scored record.

## Evidence and analysis

The operational ceiling is 0.5 GiB additional **execution** evidence, including vectors and eventual packet. Admission reserves `2 * current execution/report bytes + 16 MiB`, allowing a second local copy plus next-event headroom. The monitor stops at that reserve boundary. Actual final sizes and any overshoot must still be reported; this is not permission to hide a packaging overrun. Preflight source/review artifacts are preparation, separately measured.

The report uses 12 cells with planned denominator 16 and 24 input clusters. Known model failures retain strict primary scores; unexpected software/missing evidence is listed separately. Only complete four-D/four-R clusters use the existing target aggregator for T_b, T_h, direct redraw and 0.10/0.25 declines. A partial input has achieved counts/score lists/variance, no filled K=4 target. Equal-family means are descriptive over observed subsets; any missing family leaves the six-family mean undefined. Cross-pairs are never independent rows. Invalid evidence is prominently labeled even when earlier valid rows can still be inspected.

No routing, fitting, significance test or P03 simulation is implemented. One-query deployment remains one live feature forward, cheap features/MLP/calibration, one selected answer, and an explicitly reviewed initialization policy. Research's 50 feature passes and 192 answers are collection costs. Cached vectors do not make future live features free. No dollar tariff, beta, hardware support bound or final allocation is selected.

## v3 publication and stop corrections

`p02d_publication.write_new` publishes immutable IPC, ledger and resource records by atomic same-filesystem hard-link creation after preparation. Duplicate destinations fail. A pre-commit crash leaves at most an ignored `.pending` file; a post-commit crash leaves a complete committed record, with a possible extra temporary link. File fsync is not a claim of directory metadata durability through sudden power loss. Recovery still treats missing/corrupt committed evidence as integrity failure. This implementation was exercised with real Windows threads and a small abruptly exiting CPU-only subprocess. A filesystem that disallows hard links fails closed; it must not fall back to overwrite publication.

Ready/result readers and the child's command/control readers see a complete object or absence. Null, malformed JSON, changed command identity, invalid cancellation/finish bodies and corrupt hashes fail closed. All first session/dispatch/admission records use the same helper. stdout/stderr remain appendable diagnostic streams, never completion or authorization records. Static plan/input/auth files are hash-bound and not concurrently mutated; future authorization must be prepared using this publication protocol before enabling dispatch. The only mutable file, phase state, uses prepared atomic replacement and is not an immutable evidence record.

After stopping/waiting for a child, the supervisor validates the ledger and any committed worker results/incidents again. A safe BudgetStop writes a hash-linked `operational_stop` and independent resource/stop record. Already complete observations remain available; any dispatched slot without a result becomes `STOPPED_UNSCORED`, with its request identity and reservations retained. This is a known terminated attempt, not a successful forward, score zero, or reusable slot. Any stop blocks automatic recovery and further admission, even if interrupted before linking the independent stop artifact into the ledger. A stop before the next slot's dispatch does not consume that unexecuted slot.

An unsafe kill/wait, unknown residency, software/evidence error or corrupt/missing committed record remains an integrity incident even if a budget trigger initiated stopping. Session resource records are hash-bound from session-end events. Reports distinguish `STOPPED_INCOMPLETE` from dominant `INTEGRITY_INCIDENT`, preserve valid earlier outcomes, show achieved counts, and never synthesize missing K=4 clusters. Final reporting also detects independently published resource/stop records without their completed ledger links. No replay or continuation authority is inferred from safe cleanup.
